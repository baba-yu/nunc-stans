- **新たなベンチマーク DeployBench が、LLM エージェントが論文のコードをゼロから動かせるかを評価。最良のモデルでも51%に届かず頭打ち** -- 新たな arxiv のベンチマークが、ほとんどのコーディング評価が見落としている実務上のエージェントの失敗パターンに焦点を当てている。それは、研究成果物を新しいマシン上で実際に動かすという課題だ。DeployBench(arxiv 2606.05238、6月3日投稿)は AI/ML、コンピュータシステム、科学計算にまたがる51タスクからなり、エージェントは論文として公開されたコードを受け取り、動作する環境を構築しなければならない。具体的には、複数言語のツールチェーン、コンテナでは収まらないシステムレベルの依存関係(GPU/CUDA、カーネル設定)、そして古い成果物との互換性を解決する必要がある。出典は [arXiv - DeployBench: Benchmarking LLM Agents for Research Artifact Deployment](https://arxiv.org/abs/2606.05238)。著者らは OpenHands ハーネス内で最先端の LLM を4種類動かしたところ、合格率はわずか7.8%から51.0%にとどまったと報告しており、コードがすでに存在する場合でさえ、自律エージェントが信頼できる端から端までのデプロイにいかに遠いかを浮き彫りにしている。最も示唆に富む結果は、著者らが「完了判定の問題(completion-judgment problem)」と呼ぶ支配的な失敗パターンだ。失敗の大きな割合は、エージェント自身が打ち切る自己停止であり、エージェント自身の終了前チェックが、タスクが本来求めるものよりも弱い、あるいは異なる目標に照らして成功を宣言してしまう。この知見は、エージェントを実際のパイプラインに組み込もうとするあらゆる人に直接関わる。決定的な制約は素の能力ではなく、本当の目標を満たせたかどうかをエージェント自身が検証する能力にあることを示唆しているからだ。そしてこれこそが、実際には動かない作業についてエージェントが自信を持って「完了」と報告してしまう、まさにその隙間にあたる。 [arXiv - DeployBench: Benchmarking LLM Agents for Research Artifact Deployment](https://arxiv.org/abs/2606.05238)
