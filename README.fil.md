- **Tumama ang critical CVSS 9.9 RCE sa Flowise MCP stdio adapter (CVE-2026-40933)** — Lumitaw ngayong linggo ang ikalawang critical remote-code-execution flaw sa isang AI-agent framework. Ang CVE-2026-40933 ay nasa Flowise, ang drag-and-drop na LLM-flow builder na may mahigit 52,000 GitHub stars. Naka-rate itong CVSS 9.9 at isa itong OS command injection (CWE-78) sa Model Context Protocol stdio adapter ng Flowise. Maaaring i-configure ng isang authenticated user ang isang MCP stdio server gamit ang arbitraryong command. Ang isang one-click chatflow import ay nag-uudyok ng execution bago pa ang anumang tahasang run, na nagbibigay ng code execution sa mga pribilehiyo ng Flowise process. Naayos ito sa Flowise 3.1.0 sa pamamagitan ng maintainer-coordinated disclosure. Isang linggo matapos ang Langroid text-to-SQL flaw, ang dalawang CVSS-9-plus na framework RCE ay nagpapakitang malinaw na aktibong attack surface na ang mga self-hosted agent platform. [GitLab Advisory Database - CVE-2026-40933: Flowise: Authenticated RCE Via MCP Adapters](https://advisories.gitlab.com/npm/flowise-components/CVE-2026-40933/), [GitHub Advisory GHSA-c9gw-hvqq-f33r - Flowise: Authenticated RCE Via MCP Adapters](https://github.com/advisories/GHSA-c9gw-hvqq-f33r)

- **Tinawag ng mga researcher ang Flowise MCP patch na symptom-fix, pinupuna ang disenyo ng stdio** — Ang mas bagong development sa CVE-2026-40933 ay isang disclosure debate. Ang Obsidian Security, na naglathala ng proof-of-concept exploit code, ay nagsasabing ang allowlist-and-flag-validation patch ay "treats the symptom rather than the cause." Ito ay dahil umiiral ang stdio transport para mag-execute ng code, at maaari pa ring ipahayag ng attacker ang malisyosong gawi sa loob ng pinapayagang input. Inirerekomenda nila na i-disable ng mga operator ang stdio nang tuluyan pabor sa Server-Sent Events. Tumama ang kritisismong ito sa eksaktong alalahaning inilahad ng AI Security Center ng NSA sa kanilang Model Context Protocol Cybersecurity Information Sheet. Ang mga serialized na tool response at stdio transport ay maaaring magdala ng malisyosong payload, at ang mga agent na sumasaklaw sa maraming MCP server ay kadalasang walang privilege isolation. Ang aral dito: ang flexible at underspecified na transport layer ng MCP ay isa nang aktibong sinusuring mahinang punto. [CSO Online - Flowise's MCP implementation can run ghost commands](https://www.csoonline.com/article/4179309/flowises-mcp-implementation-can-run-ghost-commands.html), [Obsidian Security - 1-Click RCE in Flowise (CVE-2026-40933): When Is stdio MCP Actually a Vulnerability?](https://www.obsidiansecurity.com/blog/when-is-stdio-mcp-actually-a-vulnerability), [NSA - Press release: Security Design Considerations for AI-Driven Automation Leveraging the Model Context Protocol](https://www.nsa.gov/Press-Room/Press-Releases-Statements/Press-Release-View/Article/4496698/nsa-releases-security-design-considerations-for-ai-driven-automation-leveraging/)

### Predictions check

Pinagsasama ng siklo ngayon ang isang thread ng federal-governance, isang tumitinding thread ng agent-security, at isang nananatiling bullish na thread ng accelerator, kung saan ang security thread ang may pinakamabigat na timbang. Ang nag-uugnay na hibla ay simple: patuloy na nakakakuha ng konkretong halimbawa ang abstraktong kaso para ituring na hindi mapagkakatiwalaan at kontrolado-ng-umaatake ang AI tooling, nang mas mabilis kaysa sa kayang i-standardize ng mga depensa. Ang pinakamatalas na suporta ng araw ay ang Flowise CVE-2026-40933 disclosure, isang CVSS 9.9 OS command injection sa Model Context Protocol stdio adapter ng framework. Doon, ang isang one-click chatflow import ay nag-e-execute gamit ang sariling privileges ng host process nang walang confinement. Tumama ito nang pinakamalakas sa agent-harness containment-spec na hula (May 31), ang pinakamalinaw na suporta sa ngayon. Itinuturo kasi ng argumento ng Obsidian Security na ang allowlist patch ay "treats the symptom rather than the cause" ang pasanin ng enforcement sa runtime na naglulunsad at nagkukulong sa tool, hindi sa string na ibinigay dito. Isang linggo matapos ang Langroid text-to-SQL flaw, ang dalawang CVSS-9-plus na framework RCE ay nagpapalusog din sa read-only-by-default execution-guard na hula (June 5) at sa PaaS MCP-identity-gateway na hula (May 31), na pinapalawak ang lohika ng SQL-tool sa agent tool execution sa kabuuan. Binubuhay ng parehong thread ang ilang dormant na thesis nang sabay. Nakakakita ng tipikal na halimbawa ang [REVIVED] LLM-tooling-plus-kernel-CVE-chain na hula (May 2), at inaangat ng [REVIVED] Agent-in-the-Loop secret-exfiltration na hula (April 20) ng aral na ang mga self-hosted agent platform ay isa nang aktibong sinusuring attack surface. Parehong tumutugma ang mga ito sa malawak na direksyon ng pagtaas ng agent-attack-surface, hindi sa kanilang mga pinangalanang sub-category. Ang governance thread ay ang June 2 order ni Trump, na ang sentro ng grabidad ay nilinaw ng legal na pagsusuri bilang cybersecurity, hindi licensing. Inuutusan nito ang Treasury, NSA, at CISA na magtayo ng AI Cybersecurity Clearinghouse at i-benchmark ang cyber capabilities ng mga modelo. Ang paulit-ulit na tala mula sa Ropes & Gray at Freshfields na ang procurement leverage ay nagbibigay ng mandatory na hatak sa voluntary scheme ang dahilan kung bakit nagiging load-bearing ang order. Direktang isinusulong nito ang AI-assisted-vuln-triage federal-financial baseline (June 1), naghahandog ng konkretong hugis para sa frontier-lab catastrophic-risk-disclosure na hula (June 5), at binubuhay ang isang kumpol ng [REVIVED] oversight-stack na thesis (May 19, May 21, May 22) sa pamamagitan ng EO-plus-CISA-directive-plus-parallel-congressional-track na hugis nito. - **Inilabas ng mga mambabatas sa House ang discussion draft ng Great American AI Act, na nagmumungkahi ng tatlong-taong pederal na preemption ng mga panuntunang pang-estado sa frontier-AI** -- Inilabas nina Representatives Jay Obernolte (R-Calif.) at Lori Trahan (D-Mass.) ang isang bipartisan na discussion draft ng Great American Artificial Intelligence Act noong Huwebes June 4. Ito ay isang humigit-kumulang 270-pahinang teksto na nilalayong kumalap ng feedback mula sa mga stakeholder bago ang pormal na pagpapakilala, ayon sa [FedScoop - Bipartisan 'Great American AI Act' draft proposes new federal AI governance framework](https://fedscoop.com/bipartisan-great-american-ai-act-draft-proposes-new-federal-ai-governance-framework/). Ang probisyong umaakit ng pinakamaraming pansin ay isang tatlong-taong preemption ng mga batas pang-estado na partikular na nagre-regulate sa *pagbuo* ng mga frontier AI model. Haharangin ng moratoryum ang mga panuntunang pang-estado gaya ng training-data-disclosure na batas na AB 2013 ng California at bahagi ng SB 942 sa content watermarking, habang hayagang iniiwang nakalagay ang mga batas pang-estado na pangkalahatang saklaw at ang mga panuntunang pang-estado na namamahala kung paano *ginagamit o dine-deploy* ang AI, ayon sa [Roll Call - Bipartisan AI draft proposes three-year preemption of state laws](https://rollcall.com/2026/06/04/bipartisan-ai-draft-proposes-three-year-preemption-of-state-laws/). Bilang kapalit ng preemption, bumubuo ang draft ng isang pederal na layer. Hinihingi nito sa malalaking frontier developer - iniulat sa hangganang lampas sa $500 million na gross revenue noong nakaraang taon - na maglathala ng isang pampublikong "frontier AI framework" na naglalarawan sa mga teknikal at pang-organisasyong protokol na ginagamit nila upang suriin at pamahalaan ang mga catastrophic na panganib ng isang modelo (tinukoy bilang isang nakikinikinitang, materyal na panganib ng malawakang pagkamatay). Isinasabatas din nito ang Center for AI Standards and Innovation sa loob ng Commerce Department na may $100 million bawat taon na awtorisado para sa fiscal 2027-2029 upang magsulat ng mga boluntaryong gabay at suriin ang mga sistema ng AI, ayon sa [Nextgov/FCW - Lawmakers propose AI framework that would preempt state laws for 3 years](https://www.nextgov.com/artificial-intelligence/2026/06/lawmakers-propose-ai-framework-would-preempt-state-laws-3-years/413975/). Agad na nahati ang reaksyon sa linya ng preemption. Pinuri ng mga tagapagtaguyod ng kaligtasan ang pagtutok sa catastrophic-risk at loss-of-control ngunit tinawag nilang isang "generational mistake" ang paggawang pederal na hangganan sa saligan ng batas pang-estado. Nagtatakda ito sa sentral na labanan habang patungo ang draft sa isang tunay na panukala, at mahalaga ito nang direkta sa bawat frontier lab na lampas sa linya ng kita dahil ipantay nito ang rehimen ng pagsisiwalat na pinapatakbo nila. - **Isang kritikal na prompt-injection-to-RCE na depekto sa Langroid LLM-agent framework (CVE-2026-25879, CVSS 9.8) ang nagpapanatili sa agentic SQL attack surface sa sentro ng pansin** -- Isang bagong inilathalang advisory ang naglagay ng CVSS 9.8 critical na rating sa CVE-2026-25879 sa Langroid, isang sikat na open-source na framework para sa pagbuo ng mga aplikasyong pinapagana ng LLM. Nasa SQLChatAgent ng Langroid ang depekto, na nagpapatupad ng SQL na ginawa ng modelo. Dahil ang SQL na iyon ay maaaring patnubayan ng prompt injection, ang isang umaatake na kayang humubog sa input ng agent (direkta sa pamamagitan ng isang malisyosong prompt, o di-tuwiran sa pamamagitan ng paglason sa datos na babasahin ng modelo) ay maaaring pumilit ng mga mapanganib at dialect-specific na primitive. Kapag kumonekta ang agent gamit ang isang database role na may mataas na pribilehiyo gaya ng PostgreSQL `pg_execute_server_program`, MySQL `FILE`, o MSSQL `xp_cmdshell`, ang mga primitive na iyon (halimbawa ay `COPY ... FROM PROGRAM`) ay umaakyat mula sa pagnanakaw ng datos tungo sa ganap na remote code execution sa host ng database, ayon sa [GitLab Advisory Database - CVE-2026-25879: Langroid has Prompt to SQL Injection, Leading to RCE](https://advisories.gitlab.com/pypi/langroid/CVE-2026-25879/). Lumabas ang ayos sa Langroid 0.63.0, na ngayon ay nagde-default sa SQLChatAgent tungo sa isang SELECT-only na allowlist na pina-parse gamit ang sqlglot kasama ang isang dialect-aware na blocklist ng mapanganib na pattern, ayon sa [GitHub Security Advisory - Prompt to SQL Injection leading to RCE in Langroid (GHSA-mxfr-6hcw-j9rq)](https://github.com/langroid/langroid/security/advisories/GHSA-mxfr-6hcw-j9rq) ng maintainer. Ang pattern ang siyang nag-uugnay sa seguridad ng agentic AI sa kasalukuyan. Ang parehong text-to-SQL-to-database na daan ang gumawa sa aktibong pinagsasamantalahang LiteLLM proxy injection (CVE-2026-42208), kung saan ang isang ginawang Authorization header ay umabot sa isang unparameterized na key-lookup query sa pamamagitan ng error-handling path. Inayos ito sa v1.83.7 at inirerekomenda sa v1.83.10-stable, ayon sa [LiteLLM docs - Security Update: CVE-2026-42208 in LiteLLM Proxy](https://docs.litellm.ai/blog/cve-2026-42208-litellm-proxy-sql-injection). Ang aral na binibigyang-diin ng parehong depekto ay anumang LLM na pinapayagang sumulat ng SQL ay dapat tumakbo laban sa isang least-privilege, read-only-by-default na database role, dahil ang output ng modelo ay dapat ituring bilang hindi mapagkakatiwalaan at kontrolado-ng-umaatake na input. [GitLab Advisory Database - CVE-2026-25879: Langroid has Prompt to SQL Injection, Leading to RCE](https://advisories.gitlab.com/pypi/langroid/CVE-2026-25879/), [GitHub Security Advisory - Prompt to SQL Injection leading to RCE in Langroid (GHSA-mxfr-6hcw-j9rq)](https://github.com/langroid/langroid/security/advisories/GHSA-mxfr-6hcw-j9rq), [LiteLLM docs - Security Update: CVE-2026-42208 in LiteLLM Proxy](https://docs.litellm.ai/blog/cve-2026-42208-litellm-proxy-sql-injection)
