# 2_future_prediction — writer rules (Phase 3 JSON-emitting flow)

Detailed writer regulations for the LLM-driven steps in `2_future_prediction`. Phase 3 rewrite: writer prompts now produce **JSON sourcedata** conforming to the schemas in `design/sourcedata-layout.md §JSON schemas (canonical)`. Markdown is NEVER written by the LLM — `render-future-prediction-md` (Jinja2) is the single producer of `data/future-prediction/<L>/future-prediction-YYYYMMDD.md`.

## `compose-summary` — semantic contract for `summary.json` fields

`summary.json` carries three free-form prose fields. Each has a SPECIFIC role; mixing them produces redundancy with the rest of the FP report.

### `plain_language` (≤ 200 chars, ≤ 3 sentences)

Plain-language elevator pitch of the day's news cycle for the dashboard's "Plain" reader. No proper-noun chains; no internal IDs; no scope prefixes.

### `findings` (multi-paragraph dense prose)

Daily synthesis. Cross-cuts across the day's news + bridges. Surfaces high-coherence supports, dormant revivals, cross-stream patterns. References predictions by lead phrase + date (never by hash). This is the section that feels like a daily editorial summary.

### `relation_to_my_preds` (multi-paragraph dense prose) — **READ THIS BEFORE WRITING**

**EXACTLY 3 paragraphs**, one per **user standing thesis prediction** as defined in `data/reference/standing-predictions.md`. Format per paragraph:

```
The user's [first|second|third] standing prediction (<short label from data/reference/standing-predictions.md>) gains [substrate|governance|real-world] [reinforcement|densification|...] ...
```

**Critical:** this section is NOT about today's 3 fresh predictions. Those are already exhaustively covered by `news.md ## Future`, by `## Bridge` validation rows, and by the `validation_rows` schema in `bridges.json`. Repeating today's fresh preds here is the regression caught on 2026-05-11 against the 5/10 + 5/11 outputs. Sub-agents that confuse this MUST be re-prompted with this contract before re-emitting.

The 3 standing predictions are **persistent across all daily runs**. They evolve only when the user explicitly edits `data/reference/standing-predictions.md`. Sub-agents must:

1. Read `data/reference/standing-predictions.md` for the canonical 3-pred list + each thesis's evidence-class hints.
2. Read 2–3 prior days' FP markdown `## Relation to My Own Predictions` sections (e.g. `data/future-prediction/en/future-prediction-2026-05-{07,08,09}.md`) for prose-style examples.
3. Synthesize today's evidence from `news_section.json` + `headlines.json` + `bridges.json` against each standing thesis.
4. Emit 3 ordered paragraphs (1st → 2nd → 3rd), dense prose, no scope prefixes / no hash IDs / no parser anchors.

Locale fan-out: `translate-sourcedata` rewrites `relation_to_my_preds` per locale; positional/structural correspondence preserved (3 paragraphs in same order).


The legacy stream-letter writer-rules vocabulary is **gone**. There is no Bridge with a `**Bridge (Pred ID #N):**` parser anchor + `Coherence N/5` token + `Remaining gap:` token. The bridge is one JSON object per validation row with explicit fields `narrative`, `support_dimension`, `coherence`, `remaining_gap` — those internal field names live in JSON only. The renderer turns them into clean prose: "On the X prediction (Apr 27): … Strong signal. The remaining unknown is …".

## AI-notice header (literal — written by the renderer, not the LLM)

The renderer (`render_future_prediction_md.py`) injects the locale-localized notice block right after H1. Strings:

- **EN**: `> **Note:** The articles and summaries on this page are generated by Anthropic's Claude (a generative AI).`
- **JA**: `> **ご注意:** 本ページの記事および要約は、Anthropic 社の生成AI「Claude」によって作成されています。`
- **ES**: `> **Nota:** Los artículos y resúmenes de esta página son generados por Claude (IA generativa) de Anthropic.`
- **FIL**: `> **Paalala:** Ang mga artikulo at buod sa pahinang ito ay nilikha ng generative AI na Claude ng Anthropic.`

Each preceded by `<!-- ai-notice -->` on its own line. The HTML comment is the marker the post-processor and the ingest pipeline both key off.

## Per-skill JSON contracts

### `compose-validation-rows` (one sub-agent)

Output: object matching `bridges.json` schema with `validation_rows[].bridge` left as placeholder values (`narrative=""`, `support_dimension="none"`, `coherence=0`, `remaining_gap=""`). Each row must populate:

- `prediction_ref.id` — the existing prediction's hashed id (look up in DB).
- `prediction_ref.short_label` — the EN canonical short text (do NOT translate; this is the dormant-pool match identity key).
- `prediction_ref.prediction_date` — ISO date the prediction was authored.
- `today_relevance` — integer 1–5.
- `evidence_summary` — multi-line prose synthesizing today's signals; cite by lead phrase (e.g., "AMD May 5 Q1 print preview …"), not by `Pred ID`.
- `reference_links` — list of `{label, url}`; every URL must already appear in today's `data/daily-news/en/news-YYYYMMDD.md`. No external research.

Includes the **2-layer dormant longshot detection**: Layer 1 (keyword) scans today's news against each row's `Signals` column; Layer 2 (semantic) reads today's `## Headlines` + sub-headings against the snapshot's `Prediction (short)` lines. Union dedupe by ID; honest relevance score; mark revived rows with `[REVIVED]` prefix on `evidence_summary`. **No mutation of the dormant snapshot in this flow** — that's `4_weekly_memory`'s job.

### `compose-bridge` (one sub-agent per validation row)

Output: a single object matching the `bridge` field of `validation_rows[]`:

```json
{
  "support_dimension": "because | given | so_that | landing | none",
  "narrative": "<single-paragraph prose; ≤ 60 words; references the prediction by short_label + date, NEVER by `Pred ID #N`; explains why today's evidence supports/refutes that dimension>",
  "coherence": 1-5,
  "remaining_gap": "<short prose; ≤ 30 words; what's missing for higher confidence>"
}
```

Field-level rules:

- **`support_dimension`** is one of the five literals. Use `none` when no news today touches the prediction; the renderer still emits a paragraph for that row.
- **`narrative`** must NOT contain `Pred ID #N`, `Coherence N/5`, `Remaining gap:`, or any parser anchor. The renderer composes the prose paragraph; the writer just supplies the body sentence.
- **No scope prefix** in any field — `(Tech)`, `(Business)`, etc. are forbidden across the board.
- **Reference predictions by short_label + date in prose**, e.g. "On the Hyperscaler-AI-lab capital coupling prediction (Apr 26): …" — but NOT inside the `narrative` JSON field (that's the renderer's job). The writer's `narrative` is just the supporting argument, e.g., "Pentagon's May 1-3 8-vendor classified-network deal supports the prediction's structural force — once procurement freezes the laggard, the cohort recouples around the remaining vendors."
- **`coherence`** is the writer's confidence integer; the renderer turns it into a prose qualifier (e.g., 5 → "strong signal"; 1 → "weak signal").

### `compose-summary` (one sub-agent)

Output: object matching `summary.json` (a sibling of `bridges.json`):

```json
{
  "plain_language":       "<≤ 200 chars; ≤ 3 sentences; no jargon unless status='active' in glossary_terms; no scope prefix; no markdown>",
  "findings":             "<multi-paragraph prose summarizing today's evidence vs the standing prediction set>",
  "relation_to_my_preds": "<multi-paragraph prose mapping today's evidence to the user's 3 standing personal predictions>"
}
```

Field-level rules for `plain_language`:

- ≤ 200 chars (Python `len()`).
- ≤ 3 sentences (split on `[.!?]`).
- ≤ 80 chars per sentence.
- No `**` markdown.
- No proper-noun chain longer than 2 in a single sentence.

## Schema validation gate

Every sub-agent's JSON output is validated at write time against `app/skills/sourcedata_schemas.py`. On schema failure the orchestrator MUST fail-fast and re-prompt the failing sub-agent with the explicit error message.

## Forbidden token reminder

The lint check `lint-markdown-clean` (Step 8 of the orchestrator) catches Stream-jargon / parser-anchor leaks in the rendered markdown. Even though the renderer wraps prose into a deterministic shape, the writer prompts can still inject forbidden tokens INTO `bridge.narrative` or `summary.findings` (e.g. an LLM that quotes "Coherence 4/5" inside its narrative). The lint catches this. See `design/sourcedata-layout.md §Naming hygiene` for the full forbidden-token list.

## Dormant pool re-check (existing rule, retained verbatim)

The dormant snapshot at `data/memory/dormant/dormant-*.md` (latest) drives the 2-layer longshot detection in `compose-validation-rows`. Layer 1 (keyword) scans today's news against each row's `Signals` column; Layer 2 (semantic) reads today's `## Headlines` + sub-headings against the snapshot's `Prediction (short)` lines and identifies plausible relations. **Union dedupe by ID**; honest relevance score; `[REVIVED]` prefix on the `evidence_summary` field with the matching signal or heading. **No mutation of the dormant snapshot in this flow** — that's `4_weekly_memory`'s job.

`[REVIVED]` triggers `predictions.huge_longshot_hit_at = <validation_date>` in the DB; the dashboard renders a star + pulsing gold halo for ~14 days.
