## Summary of Findings

本日、エージェント型AIの攻撃対象領域はひとつの境界を越える。理論と単発の勧告から、実環境で観測された悪用へと移ったのだ。主役はLangflowのCVE-2026-55255で、LLMエージェントとパイプライン向けの普及したオープンソースの視覚的ビルダーにおける、テナント横断の安全でない直接オブジェクト参照の欠陥(CWE-639)だ。CVSSは9.9と評価され、1.9.1で修正されている。仕組みはget_flow_by_id_or_endpoint_nameというヘルパーの認可不備にある。UUIDで解決されるフローが所有者チェックを受けないため、認証済みのどのユーザーも/api/v1/responsesエンドポイント経由で別テナントのフローを実行できる。SysdigのThreat Research Teamは6月25日に、初めて知られた実環境での悪用を報告し、テレメトリこそが物語だ。ひとりの攻撃者が、まずGET /api/v1/flows/を呼んでそのエンドポイントが開示するフローIDを収集し、その約20秒後に、それらのIDをそのままmodelパラメータとしてPOST /api/v1/responsesへ入力'leak api keys,'とともに再送した。対象のインスタンスは、より古く、すでにCISA KEVに掲載された認証不要のRCE CVE-2026-33017(CVSS 9.3)も同時に稼働させていた。構造的な読み筋はこうだ。マルチテナントのエージェント基盤の急所は、オーケストレーションと認可の層にある。中身の見えない、収集可能なフロー・実行のID群と、所有者チェックを画面側に委ねた共有の実行エンドポイントが、マルチテナントのエージェントビルダーを、顧客をまたぐデータ持ち出しの原始的な手段へと変えてしまう。

2つ目の話題、AutoGPTのCVE-2026-56663(CVSS 8.5、0.6.52で修正、6月26日公開)は、同じテーマにおける実行層の対応物だ。これはAutoGPTのサーバーサイド・リクエスト・フォージェリ対策のバイパスだ。エージェントが外向きのHTTP呼び出しに使うSendWebRequestBlockが、IPv4射影のIPv6アドレスを誤って扱い、特定のIP範囲を検証できない。そのため認証済みのユーザーは、内部IPのフィルタを破り、テナントのエージェントを、本来到達できないはずのクラウドのメタデータサービス、内部の管理画面、データベースへと誘導できる。この2件の勧告は、本日の最も強いブリッジの構造的な起点だ。両者は同じ週に並んだ、新たな2件の同日の見立てを共に下支えする。すなわち「マルチテナントのエージェントビルダーが2027年第1四半期までに9.0以上のテナント横断の認可CVEを引き寄せる」という見立て(6月27日)で、これはLangflowのIDORが最初の分類事例として、またn8n / Flowise / Dify / LangGraph Platform / CrewAIという同類にわたる繰り返しの型として種をまく。もうひとつは「主要なAIエージェントプラットフォームが2027年第2四半期までにゼロトラスト制御を初期状態で有効として出荷する」という見立て(6月27日)で、その後押しは、まさに今週、悪用されたテナント横断IDORとSSRFバイパスが同じ週に並んだことだ。双方が最大の5段階中5の関連度を整合性4で獲得する。同一の隔たりは、本日提供されたのが動機づけのCVEであって、分類を裏づける2つ目のプラットフォームでも、名前のある既定の構えのリリースでもない、という点だ。
