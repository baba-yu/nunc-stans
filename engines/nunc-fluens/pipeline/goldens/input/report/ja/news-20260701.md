## Future


1. OpenAI か Google が2026年Q4までにエージェント特化のミドルティアモデルを投入する

   Anthropic が6月30日に公開した Sonnet 5 は、ミドルティアを長期タスクを担う自律エージェントの既定基盤として再定義した。BrowseComp のエージェント型検索ベンチマークと OSWorld-Verified のコンピュータ操作ベンチマークで Opus 4.8 と同等のコストパフォーマンスを主張しつつ、導入価格を入力100万トークンあたり2ドル・出力100万トークンあたり10ドル（8月31日以降は標準の3ドル/15ドル）とし、Free と Pro の既定モデルとして提供する。これにより、ブラウザ・ターミナル・ツール操作を回す高性能エージェントの動作コストはフラッグシップのおよそ3分の1まで下がる。ここはまさに、企業のエージェント向けトークン費用が積み上がる層である。予測は次のとおり。少なくとも1社のライバル最先端ラボ（OpenAI か Google の可能性が最も高い）が、自律的なエージェント作業に向けて明確に位置づけ・調整したミドルティアモデルを投入する。生の推論スコアではなくエージェント型検索とコンピュータ操作のベンチマーク同等性を売りに、入力100万トークンあたり3ドル未満の競争力ある価格で出してくる。この競争圧力は反射的なマーケティングではなく構造的なものだ。十分に高性能で最も安いエージェント実行環境が自律ループの基準価格を決めてしまえば、プラットフォーム開発者は品質基準を満たす最安のミドルティアにエージェント連携の既定を寄せる。そのためライバルは同格のティアを揃えるか、最大量の推論ワークロードを明け渡すかの二択になる。


   In plain language: Anthropic の主要ライバルのどれかが、新しい Sonnet に対抗して、エージェントを動かすための安価な中型 AI を出す可能性が高い。


2. エージェント開発フレームワークが2026年Q1までにサンドボックス化した MCP ツール実行を既定で搭載する

   6月下旬にエージェント型 AI 開発ツールで相次いだ CVE 群は、MCP サーバーとツール実行の境界に警鐘を鳴らした。Flowise の Custom MCP Server には CVSS 9.9 の OS コマンドインジェクション欠陥（CVE-2026-56274）があり、正規表現のバイパスとフラグ検証の不備により、認証済みユーザーが任意のホストコマンドを実行できた。Microsoft AutoGen Studio のコード実行に関する勧告は、コンテナ分離が不十分でエージェント生成コードが過剰な権限のままホストプロセス内で動く点に由来する。同じ時期に Crawl4AI、Langflow、picklescan も 9.6〜9.8 の RCE スコアを付けられた。予測は次のとおり。主要なオープンソースのエージェント開発フレームワーク（Flowise、AutoGen Studio、Langflow など）は、サンドボックス化した最小権限の MCP・ツール実行を、任意設定から2リリースサイクル以内に既定として搭載するようになる。この一連の失敗に共通するのは「認証済みユーザーを信頼してホスト上で実行する」という同じパターンで、単一の堅牢な既定でそれを封じられるからだ。具体的には、既定でコンテナ化されたツール実行環境、ブロックリストに代わる許可リスト方式のコマンド検証、そしてホスト権限の放棄として現れると見込む。これは、過去のインジェクション系 CVE の波が Web フレームワークに安全な既定を強いたのと同じ流れだ。


   In plain language: AI エージェントを作るためのアプリがツール経由で次々と侵害されているため、各社は安全なサンドボックス化を既定にする。


3. 2番目の最先端ラボが2026年Q1までに垂直ドメイン向けエージェントハーネスを投入する

   Anthropic が6月30日に公開した Claude Science は新しいモデルではなく、ハーネス（土台となる仕組み）だ。既存の Claude モデル（Opus 4.8 を含み、特別なアクセスは不要）を60以上の科学データベース、計算ツール、ラボ用コネクタに接続し、ソフトウェアで使われてきたコードエージェントのハーネス手法を実験科学へと広げた。差別化される製品は、汎用モデルを取り巻くツール統合とドメインスキルの層であって、重みそのものではない。これは競争上の価値がどこにあるかを描き直すもので、同じ週に arxiv に出たオーケストレーション研究（2606.31518、構成とオーケストレーションを第一級の工学課題として扱う）も、研究の最前線が同じ考えに収束していることを示している。予測は次のとおり。少なくとも他の1社の最先端ラボか主要なモデルプラットフォームが、新モデルで応じるのではなく、既存モデルの上にコネクタとスキルの層をまとめた製品版の垂直ドメイン向けエージェントハーネスを、科学・法律・金融といった特定分野を狙って2026年Q1までに投入する。このハーネスは参考例やレシピ集ではなく、正式な製品ラインになる。


   In plain language: 他の AI 企業は、新しいモデルだけでなく、既存モデルを特定分野に接続する既製ツールキットを売り出す。

### Anthropic が、Opus に迫る品質でより安く自律エージェントを回すためのミドルティアモデル Claude Sonnet 5 を投入

- Anthropic は6月30日に <a href="https://www.anthropic.com/news/claude-sonnet-5">Claude Sonnet 5</a> を公開し、刷新した中型モデルを、フラッグシップに近い品質で長期タスクのエージェントを回す最安の手段として位置づけた。売りは明確にエージェント向けだ。このモデルは計画を立て、ブラウザやターミナルといったツールを使い、数か月前ならもっと大きく高価なモデルを必要とした水準で自律的に動作するように作られている。Anthropic は推論・ツール使用・コーディング・知識労働で Sonnet 4.6（2月）から大きく前進したと主張し、中〜高負荷の設定で BrowseComp のエージェント型検索ベンチマークと OSWorld-Verified のコンピュータ操作ベンチマークにおいて Opus 4.8 と同等のコストパフォーマンスを主張する。価格は8月31日まで入力100万トークンあたり2ドル・出力100万トークンあたり10ドルの導入価格で、その後は標準の3ドル/15ドルへ上がる。Sonnet 5 は Free と Pro の既定モデルで、Max・Team・Enterprise と API でも利用できる。Anthropic はここ数週間のエージェントセキュリティの論点にも関わる安全面にも触れ、このモデルは望ましくない挙動の割合が下がり、悪意ある要求の拒否やプロンプトインジェクション攻撃での乗っ取りへの耐性が前モデルより高いとしている（<a href="https://9to5mac.com/2026/06/30/anthropic-upgrades-claude-with-new-sonnet-5-model-details-here/">9to5Mac</a>）。読み取れるのは、高性能なエージェント作業のトークンあたりコストがミドルティアから下がり続けているということだ。Gartner が指摘してきた企業のトークン費用が実際に積み上がるのは、まさにこの層である。 [Anthropic - Claude Sonnet 5 を発表](https://www.anthropic.com/news/claude-sonnet-5), [9to5Mac - Anthropic が新しい Sonnet 5 モデルで Claude を刷新](https://9to5mac.com/2026/06/30/anthropic-upgrades-claude-with-new-sonnet-5-model-details-here/)


### Anthropic が、既存の Claude モデルを60以上の科学データベースとラボ用ツールに接続するエージェントハーネス Claude Science を投入

- 同じ6月30日の周期で Anthropic は <a href="https://news.northeastern.edu/2026/06/30/anthropic-claude-science-launch/">Claude Science</a> も投入した。これは研究用のワークベンチで、注目すべきは新しいモデルではなくハーネスである点だ。すでに販売中の同じ Claude モデル（Opus 4.8 を含み、特別なアクセスは不要）を動かし、ゲノミクス、シングルセル、プロテオミクス、構造生物学、ケモインフォマティクスにまたがる60を超える科学データベースと計算ツールへの事前設定済みコネクタを重ねる。Claude Code と同様に、簡潔で高レベルの指示から意味のある作業を遂行するよう設計されており、タンパク質構造の予測や研究分野を端から端まで整理するといった生物学・化学の作業を自動化する（<a href="https://letsdatascience.com/news/anthropic-launches-claude-science-ai-research-workbench-85428f54">Let's Data Science</a>）。有料の購読者全員がすぐに利用でき、Anthropic はこの投入に合わせて、最大50件のプロジェクトに各3万ドルまでの計算クレジットを助成する AI-for-Science プログラム（選定プロジェクトには Modal が最大2,000ドルを追加）を用意した。応募は7月15日まで、プロジェクトの実施は9月から12月にかけて行われる。ハーネスとワークフローのオーケストレーションという話題にとって興味深い構造的シグナルは、差別化される製品が重みそのものではなく、汎用モデルを取り巻くツール統合の層とドメインスキルにあるということだ。これはコードエージェントのハーネス手法をソフトウェアから実験科学へ広げたものである。 [Northeastern Global News - Anthropic の Claude Science は創薬の後押しを狙う](https://news.northeastern.edu/2026/06/30/anthropic-claude-science-launch/), [Let's Data Science - Anthropic が研究用ワークベンチ Claude Science を投入](https://letsdatascience.com/news/anthropic-launches-claude-science-ai-research-workbench-85428f54)


### 6月下旬にエージェント型 AI 開発ツールで重大な RCE の CVE が相次ぐ。Flowise のカスタム MCP コマンドインジェクションは 9.9

- いま最も突かれている AI セキュリティの領域はモデルではなく、オープンソースのエージェント開発ツールそのものだ。6月23日の勧告は <a href="https://nvd.nist.gov/vuln/detail/CVE-2026-56274">CVE-2026-56274</a> を公表した。これは Flowise の Custom MCP Server 機能（3.1.2 より前のバージョン）にある CVSS 9.9 の OS コマンドインジェクション欠陥で、コマンドフラグ検証の不備とローカルファイルアクセス制限の正規表現バイパスにより、認証済みユーザーが悪意ある MCP サーバーを設定し、validateCommandFlags のブロックリストをすり抜けて docker build や npx --yes のような任意のホストコマンドを実行できる。これは6月下旬に AI/ML 開発フレームワークで相次いだリモートコード実行欠陥の広い波の一つで、Crawl4AI（CVE-2026-53753）、Langflow、picklescan も同時期に CVSS 9.6〜9.8 のスコアを付けられた。別途、<a href="https://threat-modeling.com/microsoft-autogen-studio-code-execution-june-2026/">Microsoft AutoGen Studio</a> のコード実行の弱点（6月23日公表）はコンテナ分離の不足に由来し、エージェント生成コードが過剰な権限のままホストプロセスの文脈で実行され、意図したサンドボックスを抜け出す。同じ7日間の期間には、Lazarus Group に悪用されたと報じられる Mastra AI のプロンプトインジェクションから RCE への欠陥や、CISA の Known Exploited Vulnerabilities カタログに追加された LiteLLM の SSRF／逆シリアル化欠陥も見られた。共通する筋は MCP サーバーとツール実行の境界にあり、エージェントがツールを呼び出す配管部分に、悪用可能なコードが集まっている。 [NVD - CVE-2026-56274（Flowise Custom MCP Server のコマンドインジェクション、CVSS 9.9）](https://nvd.nist.gov/vuln/detail/CVE-2026-56274), [Threat-Modeling.com - Microsoft AutoGen Studio のコード実行（2026年6月）](https://threat-modeling.com/microsoft-autogen-studio-code-execution-june-2026/)


### エージェントのオーケストレーションに関する新しい arxiv 研究が、同じ週にエージェント型ワークフローの研究最前線を進める

- 6月29日に arXiv へ投稿された新しい研究が、マルチエージェントのオーケストレーションという話題を前へ進めている。Stefanie Rinderle-Ma らによる <a href="https://arxiv.org/abs/2606.31518">「Design and Implementation of Agentic Orchestrations and Orchestration of Agents」（2606.31518）</a>は連携の問題に正面から取り組み、エージェントをどう構成しオーケストレーションするかを、個々のエージェントに後付けする課題ではなく第一級の工学課題として扱う。同じ日には Yankai Jiang らによる <a href="https://arxiv.org/abs/2606.31763">「A Self-Evolving Agentic System for Automated Generation and Execution of Biological Protocols」（2606.31763）</a>も出た。これはラボのプロトコルを生成・実行し、時間とともに適応する自律システムで、Anthropic が6月30日に製品化した実験科学向けエージェントハーネスの方向性を研究側で映したものだ。同日に投稿された植物フェノタイピングのエージェント型フレームワーク（2606.31831）と合わせると、6月29日の一群は、ドメイン特化の科学の場でオーケストレーションと自己進化的な自律性へ文献が収束していることを示す。まさに商用ハーネス製品がいま狙っている領域だ。 [arXiv - Design and Implementation of Agentic Orchestrations and Orchestration of Agents（2606.31518）](https://arxiv.org/abs/2606.31518), [arXiv - A Self-Evolving Agentic System for Automated Generation and Execution of Biological Protocols（2606.31763）](https://arxiv.org/abs/2606.31763)
