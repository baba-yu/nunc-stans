### MLの攻撃対象領域が理論から実戦の悪用へ：エージェント構築ツールLangflowのテナント横断の欠陥が実環境で突かれる

- 6月25日、Sysdigの脅威リサーチチームは、CVE-2026-55255が実環境で悪用された初の既知事例を報告した。これは、LLMエージェントとパイプラインを組むための人気オープンソースのビジュアル構築ツールLangflowに存在する、テナント横断の安全でない直接オブジェクト参照（IDOR）の欠陥だ。CVSS 9.9と評価され、Langflow 1.9.1で修正されている。問題はget_flow_by_id_or_endpoint_nameというヘルパーにある。フローがUUIDで解決されるとき、データベース照会が所有者チェックを一切行わないため、認証済みのユーザーは誰でも、そのフローIDを/api/v1/responsesエンドポイントに渡すだけで別テナントのフローを実行できてしまう（CWE-639、ユーザー制御のキーによる認可バイパス）。Sysdigのテレメトリで注目すべきは、その連鎖のさせ方だ。あるオペレーターはまずGET /api/v1/flows/を呼び出し、そのエンドポイントが開示するフローIDを収集した。そして約20秒後、それらのIDをそのままmodelパラメーターとしてPOST /api/v1/responsesに渡し、入力に「leak api keys」を指定して再生した。さらに同じインスタンスに対して、認証不要の旧来のRCEであるCVE-2026-33017（CVSS 9.3、すでにCISAの既知悪用脆弱性カタログに掲載済み）も実行していた。構造的に読み取れるのは、今週前半にMLのフィーチャーストア層で顕在化したのと同じ流れが続いているということだ。エージェント基盤の弱点は、オーケストレーションとメタデータの層にある。フロー実行エンドポイントの認可の隙間ひとつで、マルチテナントのエージェント構築ツールが、顧客をまたいでデータを抜き取る手段に変わってしまう。1.9.1より前のLangflowを運用している者は、いますぐアップグレードし、露出したフローIDはすでに採取されているものとみなすべきだ。 <a href="https://webflow.sysdig.com/blog/understanding-langflow-cve-2026-55255-and-why-higher-cvss-vulnerabilities-arent-always-the-most-exploited">Sysdig - ### AutoGPTにSSRF防御の回避が見つかり、エージェント実行基盤の背後にある内部サービスが露出する

- 継続的に動くAIエージェントを構築・配備・実行するためのオープンソース基盤AutoGPTに、新たな高深刻度の欠陥が見つかり、6月26日にCVE-2026-56663として公開された。CVSS 8.5と評価され、AutoGPT 0.6.52で修正されている。これは、AutoGPTのサーバーサイドリクエストフォージェリ（SSRF）防御を回避するバグだ。エージェントが外向きのHTTP呼び出しに使うSendWebRequestBlockが、IPv4射影IPv6アドレスの扱いを誤り、特定のIP範囲を検証できていない。そのため認証済みのユーザーは、内部IPフィルターをくぐり抜けるリクエストを組み立て、ホストのプライベートネットワーク上のサービスに到達できる。問題のブロックは、エージェントのワークフローに組み込まれた汎用のWebリクエスト部品であるため、実際の影響としては、テナントのエージェントが、本来は到達できないはずの内部エンドポイント、すなわちクラウドのメタデータサービスや内部の管理画面、データベースなどを探ったり引き出したりするよう仕向けられてしまう。NVDの項目には、NIST独自の補強情報はまだ追加されておらず、GitHub CNAの評価に依拠していると記されている。この件は、エージェント実行層がなぜCVEを引き寄せ続けるのかを示す分かりやすい例だ。任意のURLをエージェントの代わりに取得することだけを役目とするブロックは、その仕組み上どうしてもSSRFの入り口になり、アドレス正規化における解析の隙間ひとつで再び口が開いてしまう。0.6.52より前のAutoGPTを運用している者は、アップグレードし、エージェント実行基盤からの外向き通信を絞り込むべきだ。 <a href="https://nvd.nist.gov/vuln/detail/CVE-2026-56663">NVD - CVE-2026-56663の詳細（IPv4射影IPv6アドレスを介したAutoGPTのSSRF防御回避、0.6.52で修正）</a> [NVD - CVE-2026-56663 Detail (AutoGPT SSRF-protection bypass via IPv4-mapped IPv6 addresses, fixed in 0.6.52)](https://nvd.nist.gov/vuln/detail/CVE-2026-56663)
