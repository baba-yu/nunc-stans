- **vLLM v0.23.0 が Model Runner V2 と Rust フロントエンドをデフォルト化** — vLLM プロジェクトは6月15日に v0.23.0 をタグ付けし、200 名のコントリビューター(うち 63 名は初参加)による 408 件のコミットを取り込み、開発中の複数のサブシステムをデフォルトの状態へと押し進めた。目玉は DeepSeek-V4 サポートのさらなる成熟である。改良されたアテンションカーネル、Mixture-of-Experts の取り扱い、そしてスパースなマルチヘッド潜在アテンションのメタデータの分離により、このアーキテクチャが各バックエンドにわたってよりクリーンに動く。これまで Qwen3 でのみデフォルトだった、より新しい Model Runner V2 の実行パスは、Llama と Mistral の dense モデルでもデフォルトになり、FlashInfer サンプラーと中断可能な CUDA グラフを獲得した。Rust フロントエンドは、ストリーミングの generate エンドポイント、動的な LoRA ロード、さらなるツール呼び出しパーサーを取り込み、従来の Python サーバーとの差を縮めている。このリリースではさらに、Gemma 4 のサポート、Transformers v5 互換性、そしてオブジェクトストアを二次層とする多層 KV キャッシュのオフロード基盤が加わり、あわせて Step-3.7-Flash、Cosmos 3 Reasoner、JetBrains Mellum v2、Granite Speech Plus、Cohere Mini Code が新たにサポートされた。報告されているマイクロ最適化には、CUTLASS の FP8 スケール付き行列積でのパディング回避(そのパスで約 20 パーセント)や、MoE permute バッファの事前確保(おおよそ 9 〜 14 パーセント)が含まれる。リリースノートはエンドツーエンドのスループットに関する主張までは踏み込んでいないため、本番での改善はモデルとバックエンドに左右される。 [vLLM v0.23.0 release notes (GitHub)](https://github.com/vllm-project/vllm/releases/tag/v0.23.0)

- **MosaicQuant が重みを dense とスパースの4ビット部品に分割する** — 6月14日に arXiv へ投稿された論文(arXiv:2606.15652、cs.LG および cs.CL)は、MosaicQuant を提案している。これは4ビットの大規模言語モデル量子化の手法であり、重み行列の dense な大部分を圧縮することと、4ビットのグリッドが切り捨てがちな、まれに現れる大きな値の外れ値を忠実に保つこととの間の緊張に対処することを狙っている。MosaicQuant は混合精度のフォーマットに頼るのではなく、各重み行列を、大半の値を捉える dense な4ビットのベース成分と、最も誤差に敏感なブロックでの量子化誤差を補正するスパースな4ビットの残差成分とに分解する。これにより両者とも4ビットにとどまる。この2部構成の表現が、混合精度の手法が通常支払うオーバーヘッドを再び持ち込まないよう、著者らは ZipperEngine を追加した。これはスパースな残差の計算を、重なり合うパイプラインを通じて dense な4ビットの行列演算に折り込み、統一された低ビットの実行パスを保つ。LLaMA3 と Qwen3 のモデルでは、この手法は FP16 に近い精度を保ちながら、16 ビットのベースラインに対して最大 1.24 倍の高速化をもたらすと報告されている。単一の論文による結果がつねにそうであるように、数値は著者ら自身のものであり、独立した再現とより広いモデルでの検証を待つ段階にある。とはいえ本研究は、4ビットのサービングを、損失の大きい代替手段ではなく、メモリに制約のあるローカルデプロイのデフォルトにしようという取り組みにおける、具体的なデータポイントである。 [arXiv:2606.15652 - MosaicQuant: Inlier-Outlier Disaggregation for Unified 4-Bit LLM Quantization](https://arxiv.org/abs/2606.15652)

### 量子化の研究: MosaicQuant は重みを dense な 4 ビットのベースと、スパースな 4 ビットの残差に分割し、単一の低ビットパイプラインで動かしながら FP16 に近い精度を保つ

- 6月14日に arXiv へ投稿された論文(arXiv:2606.15652、cs.LG および cs.CL に分類)は、MosaicQuant を提案している。これは 4 ビットの大規模言語モデル量子化の手法であり、重み行列の dense な大部分を圧縮することと、4 ビットのグリッドが切り捨てがちな、まれに現れる大きな値の外れ値を忠実に保つこととの間に長く存在してきた緊張に対処することを狙っている。MosaicQuant は混合精度のフォーマットに頼るのではなく、各重み行列を、大半の値を捉える dense な 4 ビットのベース成分と、最も誤差に敏感なブロックでの量子化誤差を補正するスパースな 4 ビットの残差成分とに分解する。これにより両者とも 4 ビットにとどまる。この 2 部構成の表現が、混合精度の手法が通常支払うオーバーヘッドを再び持ち込まないよう、著者らは ZipperEngine を追加した。これはスパースな残差の計算を、重なり合うパイプラインを通じて dense な 4 ビットの行列演算に折り込み、統一された低ビットの実行パスを保つ。LLaMA3 と Qwen3 のモデルでは、この手法は FP16 に近い精度を保ちながら、16 ビットのベースラインに対して最大 1.24 倍の高速化をもたらすと報告されている。単一の論文による結果がつねにそうであるように、数値は著者ら自身のものであり、独立した再現とより広いモデルでの検証を待つ段階にある。とはいえ本研究は、4 ビットのサービングを、損失の大きい代替手段ではなく、メモリに制約のあるローカルデプロイのデフォルトにしようという継続的な取り組みにおける、具体的なデータポイントである。 <a href="https://arxiv.org/abs/2606.15652">arXiv:2606.15652 - MosaicQuant: Inlier-Outlier Disaggregation for Unified 4-Bit LLM Quantization</a> [arXiv:2606.15652 - MosaicQuant: Inlier-Outlier Disaggregation for Unified 4-Bit LLM Quantization](https://arxiv.org/abs/2606.15652)
