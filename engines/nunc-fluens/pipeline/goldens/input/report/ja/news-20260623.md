- **Unsloth の Dynamic GGUF が 744B GLM-5.2 を単一ワークステーションに収める** — Unsloth は、Z.ai が新たにオープンウェイト化した GLM-5.2 の Dynamic GGUF 量子化版を公開した。GLM-5.2 は 7,440 億パラメータの mixture-of-experts モデル（アクティブは約 40B）で、100 万トークンのコンテキストウィンドウを持ち、データセンターの外でもローカル実行できるようになった。この精度選択型の方式は、精度に敏感な層を 8 ビットまたは 16 ビットに引き上げ、残りを 1 ビットまたは 2 ビットに下げることで、1.51TB のチェックポイントを、2 ビットの UD-IQ2_M ビルドで約 239GB（84% 削減）に、1 ビットビルドでおよそ 217GB（約 86%）まで縮める。マルチ GPU クラスタではなく、メモリを多く積んだ単一ノードの 1 台に収まる大きさだ。リリースは Unsloth Studio によるローカル実行と組み合わさり、GLM-5.2 はコーディングと推論でクローズドな最前線に迫るベンチマーク結果だと位置づけられる。圧縮と品質の主張は Unsloth 自身のもので第三者による再現はなく、ここまで攻めた 1-2 ビット量子化は、メモリ削減と引き換えに無視できない精度を犠牲にする。 [AIToolly - Unsloth enables local execution of GLM-5.2, a 744B-parameter open model with a 1M context window](https://aitoolly.com/ai-news/article/2026-06-23-unsloth-enables-local-execution-of-glm-52-a-744b-parameter-open-model-with-1m-context-window)

## Future


1. Q4 2026 までに、最前線級のオープンウェイト LLM が 256GB 以下の単一ノードで動く

   最前線級のオープンウェイトモデル（コーディングと推論でクローズドソースの最前線に迫るベンチマーク結果を出した、GLM-5.2 / 700B 超の mixture-of-experts クラスのリリース）が、Q4 2026 の終わりまでに、合計 256GB 以下のメモリを積んだメモリ潤沢な単一ワークステーションノードで実証可能な形で動くようになる。これは攻めた 2 ビット未満の精度選択型量子化によるもので、再現可能なレシピが公開され、品質はベンダーの自己申告ではなく公開ベンチマークで測られる。Unsloth の Dynamic GGUF ビルドはすでに Z.ai の 744B GLM-5.2 を 1.51TB のチェックポイントからおよそ 217-239GB まで縮めているが、その圧縮率と品質の数値は Unsloth 自身のもので未検証であり、ここまで攻めた 1-2 ビット量子化はメモリと引き換えに無視できない精度を犠牲にする。この予測は、そうしたレシピが少なくとも 1 つ第三者によって再現され、その精度保持率が公開され、最も重いオープンウェイト層がマルチ GPU クラスタの領域から単一ノード・オンプレミスの手の届く範囲へと移ったことが裏づけられたときに的中とする。これは現在続く住み分けをより鮮明にする。高度な、あるいは最高品質の作業は依然としてクラウド API に流れる一方、日常的でプライバシーに配慮が必要なワークロードは、自前のハードウェア上でローカルに動かせる場面が増えていく。


   In plain language: 2026 年後半までに、最大級でトップ層のオープン AI モデルの一つが、サーバー群ではなく 1 台の高性能コンピュータで動くようになる。


2. Q4 2026 までに、OpenClaw が既定でツールとネットワークを拒否する設定を初期状態で出荷する

   名のあるオープンなコーディングエージェントのハーネスが、Q4 2026 までに、最小権限の実行をオプトインのフラグではなく出荷時の初期状態の既定として出してくる。最有力の先行者は OpenClaw だ。その 2026.6.x 系の 6 月リリースは、すでに具体的なインジェクション経路をふさぎ、Docker サンドボックスの境界を厳しくし、Browser の CDP エンドポイント検証を追加し、SSH トンネルのチェックをループバックに固定し、安全でない長さのツール・パッケージ・レスポンスを拒否し始めている。この予測が求めるのは次の一歩だ。安定版の新リリースで、既定のプロファイルがツール呼び出し・外向きのネットワークアクセス・MCP 認証情報の露出を、運用者が明示的に許可しない限り拒否し、まっさらなインストールが追加設定なしでサンドボックス化かつ制御された状態で動くようにすること。NVIDIA の NemoClaw（OpenShell サンドボックス周りでより厳しいネットワークポリシーの既定値）と Nous Research の Hermes Agent（MCP 認証情報のフィルタリング・SSRF 対策・Tirith の事前実行スキャン）は、先に到達しうる同方向の対抗馬だ。きっかけは、収れんしつつあるセキュリティの裏付けにある。OWASP の 2026 年エージェント型レポートはほぼすべてのリスクカテゴリを実在の CVE に結びつけ、Claude Code を注意喚起の多いコーディングエージェントのリポジトリの一つに数えており、StakeBench はテストしたどのエージェント構成もプロンプトインジェクションに耐えなかったと示した（間接 41-68%、直接は 79% 超）。モデル層を堅牢にできないなら、防御はハーネス層が担うことになり、最小権限は既定であってこそ機能する。検証方法: タグ付きリリース、あるいはその変更履歴やドキュメントが、機能・ネットワーク・MCP 認証情報の制御がオプトイン設定の奥ではなく、まっさらなインストールで既定で有効になっていると明記していること。


   In plain language: 人気のコーディングロボットが、自らの危険な動作を既定でブロックするようになり、設定を変えなくても安全でいられる。


3. Q2 2027 までに、AI エージェントの調達にプロンプトインジェクション耐性の数値基準が加わる

   標準化団体・規制当局、あるいは大手の企業や政府の調達担当が、定量化されたプロンプトインジェクション耐性スコアを、エージェント型 AI の調達ゲート・フレームワークの管理項目・認証における合否の明示的な要件として掲げる。きっかけは、今期に起きた、仮定から実測への転換だ。OWASP の State of Agentic AI Security and Governance v2.01 は、いまやほぼすべてのエージェント型リスクカテゴリを具体的な CVE・ベンダーの注意喚起・侵害報告に結びつけ、注意喚起の多いリポジトリ（n8n 57、Claude Code 22、AutoGPT 15、Dify 13、Roo-Code 11）を順位づけ、プロンプトインジェクションを自らの Top 10 の 10 カテゴリのうち 6 つに対応づけた。並行して、StakeBench ベンチマーク（南洋理工大学・ST Engineering・IBM Research・イリノイ大学アーバナ・シャンペーン校）は 3,168 回の敵対的試行を実施し、間接インジェクションの成功率は 41.67%-68.16%、直接攻撃は 79% 超で、テストしたすべての構成がそうなり、堅牢な振る舞いの領域に収まったものはなかったと示した。攻撃の種類が、記録された事案の系譜と、数値の合格しきい値を持つ公開ベンチマークの両方をそろえると、買い手はベンダーの自己申告を受け入れるのをやめ、計測可能な基準を契約に書き込み始める。最初のこうしたゲートは、「プロンプトインジェクションを緩和する」と文章で求めるのではなく、名のあるベンチマークか、インジェクション成功率の数値上限を引くと見込まれる。これにより耐性は、ベストエフォートの主張ではなく監査可能な合格基準となり、OWASP/StakeBench の数値に下流での使い手が生まれる。


   In plain language: 買い手は、扱えると約束させるだけでなく、巧妙な入力に耐えるかを実際のスコアで AI エージェントに求め始める。
