## Future


1. MCP チャネルへのインライン・ポリシー適用が2027年Q1までにプラットフォームの既定機能として普及する

   Zscaler は6月9日の Zenith Live 2026 で AI Broker を発表した。これは MCP およびエージェント間(A2A)チャネルにインラインで組み込まれ、ネットワーク層でエージェントごとの権限を適用する、業界初の製品として位置づけられる。アプリケーション層ではなくネットワーク層で適用されるため、明示的なポリシー承認なしにエージェントの呼び出しがネットワークを通過することはない。同じ週、Databricks は6月16日の Data + AI Summit で Agent Bricks を発表し、MCP と Unity Catalog を統合した。これにより企業チームは、どのエージェントがどのデータソースへ MCP 経由でアクセスできるかを SQL で記述したセキュリティポリシーで制御できる。無関係な二つの本番プラットフォームが同一週に同じ設計へと収束したこと——これが構造的なシグナルだ。MCP チャネルへのアクセス制御は、エージェントを構築した後に付け足すアドオンから、エージェントランタイムがツール呼び出しをプロセス境界の外に出す前に呼び出すポリシーエンジン、つまりプラットフォームの既定機能へと固まりつつある。本予測の中核はこうだ。MCP チャネルへのポリシー適用を周辺の付け足しではなく、第一級のランタイムの既定機能として扱うこのパターンが、すでに出荷している二社を超えて第三の主要エージェントプラットフォームへと広がっていく。具体的で反証可能な実現条件は次のとおり。2027年Q1(2027年3月31日まで)に、Zscaler の Zero Trust Exchange および Databricks の Agent Bricks とは別の第三の主要エージェントプラットフォームまたはクラウドプロバイダーのエージェントランタイムが、エージェントごとの権限制御を備えた文書化された本番品質のMCPチャネル・インライン・ポリシー適用を、既定または第一級機能として公式製品ページまたは GA 発表とともに出荷すること。該当しないものは次のとおり。アドオン連携として販売されるサードパーティのプロキシ。GA への道筋が文書化されていないクローズドベータまたはプレビュー。MCPチャネル層ではなくアプリケーション層のみで適用するプラットフォーム(例:プロンプトガードや出力フィルター)。製品が出荷されていないベンダー発表。2027年3月31日時点で Zscaler と Databricks のみがエージェントランタイムの既定機能としてインラインMCPチャネル・ポリシー適用を提供している場合、この予測は外れとなる。


   In plain language: 二つの大手 AI プラットフォームが、AI エージェントが外部ツールと通信する際に許可確認を義務づける仕組みを導入した。まもなく第三の主要プラットフォームも同様の機能を備えるはずだ。


2. OpenSharing が2027年Q3までに組織横断の AI 資産共有の標準プロトコルになる

   6月10日、Databricks と Linux Foundation は OpenSharing を発表した。これは Delta Sharing を拡張し、エージェントのスキル・AI モデル・非構造化データをカバーするベンダー中立のオープンプロトコルで、独自のマーケットプレイスなしに組織横断でゼロコピーの AI 資産共有を可能にする。創設パートナーの顔ぶれは商業的に重要だ。OpenAI、SAP、Stripe、Atlassian、Amadeus が名を連ねる。これはニッチなデータエンジニアリングの標準ではなく、エンタープライズ SaaS(SAP、Atlassian)、決済インフラ(Stripe)、フロンティアモデルプロバイダー(OpenAI)の交点に OpenSharing を置くものだ。事業面の本質はこうだ。これら創設パートナーがネットワーク効果をもたらす。OpenSharing でパートナーとエージェントスキルを共有する企業は、独自の点対点の統合を組む必要がなくなる。これにより、OpenSharing 対応ベンダーを選ぶコストが下がる。歴史的に見て、大手クラウドデータ企業(Databricks)と中立の財団(Linux Foundation)に加え、SaaS 大手が相当数参加するベンダー中立プロトコルは、双方向の需要が明確なユースケースでは、立ち上げから事実上の標準まで12〜24か月で達する。ファイル形式(Parquet)、テーブル形式(Delta、Iceberg)、コンテナランタイム(OCI)がこの流れをたどった。具体的で反証可能な実現条件は次のとおり。2027年Q3までに、少なくとも三社の追加の Fortune 500 SaaS またはクラウドベンダーが OpenSharing との互換性または統合を公式に発表すること。発表は Databricks または Linux Foundation のプレスリリース、OpenSharing 公式仕様への GitHub マージ、またはデータ・AI カンファレンスでの指名発表に基づく。該当しないものは次のとおり。ベンダーレベルの関与なしに個々の顧客が実装した場合。OpenSharing の AI 資産拡張なしに Delta Sharing のみで構築した統合。Fortune 500 以外の採用者。一般提供の実装のない「近日公開」のロードマップ項目。反対側のリスクは、ハイパースケーラー(AWS、Microsoft、Google)がそれぞれ独自の資産共有の仕組みを支持し、市場を分断して OpenSharing が SaaS パートナーシップのしきい値を超えられない可能性だ。


   In plain language: 大企業が AI ツールを共有するための新しいオープン標準に参加した。このため、企業間で AI を共有する主流の方法になる公算が大きい。


3. 米国の輸出管理制度が2027年Q1までに防御的サイバー AI の例外基準を整備する

   6月12日の指令で Fable 5 と Mythos 5 の提供が停止された。停止の根拠は、コードベースを読み込んでソフトウェアの欠陥を修正するよう求めるジェイルブレイク手法だとされる。しかしセキュリティ研究者の Katie Moussouris が6月16日に指摘したとおり、問題とされた機能はまさにサイバー防御で AI が最も価値を発揮する作業であり、同じ機能は GPT-5.5 を含む競合システムにも存在する。Anthropic は、このような狭義の「ジェイルブレイク即回収」基準を業界全体に適用すれば、フロンティアモデルの新規展開がすべて止まると明言している。現在進行中のワシントンでの交渉——Anthropic が上級技術スタッフを派遣し、一部の当局者が技術的な妥協案に前向きなシグナルを出している、異例の速さで動く交渉——が、不可避な解決への圧力を生んでいる。どのような妥協案も、攻撃的なコード修正と防御的なコード修正の間に実効性のある境界線を引くか、防御的なセキュリティの明示的な例外を設けるかのいずれかでなければ、長続きしない。本予測は、この経緯が持続的な政策として結実するというものだ。2027年Q1(2027年3月)までに、商務省の BIS、議会委員会、またはNIST/CISA の公式ガイダンス文書が、許容される防御的セキュリティ AI の能力と回収基準を引き起こす攻撃的なものを区別する基準を公表することが見込まれる。該当するもの:連邦政府の文書(規則、ガイダンス、または委員会報告)であり、AI 支援による脆弱性修復またはコード解析を、明確な境界条件を持つ認められた防御的用途カテゴリとして明示的に取り上げているもの。該当しないもの:政府報道官の非公式発言、個別企業との交渉によるライセンス免除、裁判所命令、または連邦政府の公式な裏づけのない業界白書。


   In plain language: 米国政府がハッキングリスクを理由に AI モデルの提供を停止したが、同じ機能がコンピュータの防御にも使われるため、当局者は両者を区別するルールを策定することになる。
