3. MCP の stdio トランスポートが、エージェントフレームワーク全体で 2027 年 Q1 までに既定で無効になる

   Flowise の Custom-MCP RCE（CVE-2026-40933）に対する動作する概念実証と、その公式パッチを回避できることの実証が組み合わさり、stdio トランスポートは利便性のための既定から、バージョンを上げるだけでは直せない負債へと変わりました。この欠陥は単一のコーディングミスではなく構造的なものであるため、取り込んだワークフローファイルは、被害者が開いた瞬間にサンドボックス化されていない子プロセスを起動してしまいます。そして協調的な MCP サプライチェーン勧告は、検証されないコマンドがそのままサブプロセスに渡る同じパターンを、LiteLLM、Agent Zero、LangBot、Windsurf などにわたって跡付けています。セキュリティ上の指針はすでに一つの指示に収束しています。stdio を無効にして Server-Sent Events を用い、取り込んだ MCP 設定はいずれも信頼できないコードとして扱う、というものです。この収束が、ホワイトハウスが 7 月 7 日の週に自主的なフロンティアモデルの標準枠組みを整えようとしているまさにそのときに到来したことで、メンテナーにとっても、立ち上がりつつあるエージェントセキュリティの基準にとっても、標準化すべき明白な堅牢化のレバーが一つ与えられます。主要なエージェントフレームワークは、stdio ベースの MCP 実行を、明示的な信頼プロンプトやサンドボックスの背後でオプトインへと切り替え、SSE または同等に隔離されたトランスポートを出荷時の既定にすると見込まれます。これにより、設定ファイルがひそかにシェルアクセスと化すことはなくなります。ここでの結び付きはセキュリティが政策を動かす形であり、実環境で動くパッチ耐性のある悪用クラスが、最初のエージェントセキュリティ規範が書かれる際の具体的なテストケースになります。


   In plain language: 直しにくい攻撃手口によって、AI ツールが取り込んだファイルのコードを実行してしまったため、これらのツールは既定でそのモードを信頼しなくなる。
