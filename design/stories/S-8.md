# S-8 — A new app in one sitting (Phase E)

I design a new tiny app in FourFive chat and use its generated UI in
the same session, with its data file created in the vault. (v1 plan §4,
verbatim.)

This is the generality proof (plan PE14): the app is deliberately NOT
pre-designed anywhere — it is invented at execution time and must be
unrelated to runway-tracker. "Same session" is literal: one FourFive
chat session, one sitting, no rebuild or restart of the stack between
designing and using (the bundle is data; apps-host discovers it by
scan — PE3/PE6).

Setup:

    export NS_DATA=$(mktemp -d)      # scratch store, bootstrapped
    just up                          # stack running BEFORE the session
                                     # starts and untouched throughout

Pass (mechanical):

    # one FourFive chat session, wall-clock noted at start and end
    design a tiny app in chat (2+ entities, ≥1 declared metric,
    mock_ui screens) → blueprint accumulates versions as usual
      → freeze + Generate bundle from the UI
      → versions/<NNN>/bundle/ appears under
        $NS_DATA/artifact/apps/<slug>/ with the five files
        (app.json, schema.sql, mcp-tools.json, ui.json,
        tests/scenarios.json)

    # use it, same session, no restart
    open http://127.0.0.1:8720/apps/<slug>/
      → the generated UI renders the designed screens; create and
        edit rows; archive one (soft-delete — it leaves the default
        list, ?archived=1 still shows it)
    $NS_DATA/apps/<slug>/data.sqlite exists with the rows ("its data
    file created in the vault")
    curl :8720/apps/<slug>/api/metrics → the declared metric returns
        a value

    # the freeze held while we used it
    re-generating the same version reproduces identical bytes; an
    in-place patch against the frozen version is refused (F7 — plan
    PE11)

Acceptance: the same-session clock (design → use without restart),
the five bundle files, the data file in the store, and the freeze
refusal. Evidence (session transcript, `ls` of the bundle dir, the
sqlite row dump, wall-clock note) → design/verification/phase-e.md.
