# Integrated PRD v0.2: Human Thought Augmentation System

## 1. Product Definition

### 1.1 Name

Working name: **Human Thought Augmentation System**

Alternative names:

* External Brain
* State-Aware Second Brain
* Intent-Attached Memory
* Cognitive Router
* Second Brain OS

This PRD uses **Human Thought Augmentation System** as the working name.

### 1.2 One-line Definition

Human Thought Augmentation System is a second brain that strengthens human thinking by separating AI-generated external knowledge from the user’s own understanding, and by reconnecting the user’s hypotheses, decisions, and actions to their current cognitive state.

### 1.3 Positioning

This product is not:

* An information warehouse
* A note-taking app
* A general-purpose chatbot
* An autonomous agent
* A task manager
* A search engine
* A mere memory database

This product is:

* An external cognitive system that models the user’s understanding, hypotheses, decisions, and actions
* A system that reconnects past thinking assets to the user’s current INTENT
* A cognitive router that controls AI generation so that it does not overwrite human thought
* A system that maintains the cognitive load range in which the user can still form, accept, reject, and connect hypotheses to action

---

## 2. Problems to Solve

### 2.1 The Hollowing-out of the Second Brain

Conventional second brains are too focused on storage, organization, and search.

The problem is not that information is not saved.
The problem is that saved information is not reconnected to the user’s current questions, decisions, and actions.

Stored records do not become knowledge assets by being stored.
They become useful only when they affect the user’s current or future understanding, judgment, or action.

### 2.2 Confusion Between AI Output and User Knowledge

What AI explains is not automatically user knowledge.

AI output should be treated as one of the following:

* AI Response Memory
* External Knowledge
* Research result
* Reference information
* Hypothesis candidate

User knowledge should generally be inferred only from the user’s own statements, choices, acceptances, rejections, discomforts, distinctions, and decisions.

### 2.3 INTENT Loss

AI can rapidly generate large volumes of information, options, arguments, plans, and artifacts.

However, when this causes the user to enter the following state, AI is no longer augmenting thought. It is outsourcing thought.

* The user no longer knows what they were trying to do
* The user no longer knows why they were doing it
* The user no longer knows which hypothesis they were acting on
* The user no longer knows what criteria they were using
* The user no longer knows what they themselves should do next
* The user can no longer accept or reject AI output
* AI output starts determining the next question or decision automatically

This state is called **INTENT loss**.

### 2.4 Misregulated Cognitive Load

AI can reduce cognitive load, but if it reduces too much, the user stops thinking.

Loads that should be reduced:

* Exploration noise
* Redundant information
* Reading burden
* Formatting burden
* Memory-retention burden
* Irrelevant issues
* Overlong AI responses

Loads that should remain:

* Discomfort
* Hypothesis generation
* Holding decision criteria
* Acceptance
* Rejection
* Integration
* Conversion into next action

The role of the product is not to reduce cognitive load to zero.
Its role is to keep cognitive load within the range where the user can maintain their own thinking.

### 2.5 Wrong-direction Execution Support

AI agents and execution-support systems can accelerate the user even when the user has entered execution mode while facing the wrong direction.

What is needed is not a brake that kills the user’s execution momentum.
What is needed is a lane-keeping mechanism that detects drift from higher-level goals, assumptions, constraints, and reversibility.

## 3. Product Principles

### 3.1 The Goal Is Human Thought Augmentation

The goal is not cognitive load control itself.
The goal is to strengthen human thinking.

The system strengthens:

* Exploration
* Understanding
* Hypothesis formation
* Decision-making
* Action
* Learning recovery

### 3.2 Separate AI External Knowledge from User Understanding

The following must not be mixed into the same memory layer:

* Answers generated by AI
* Knowledge from external documents
* Things the user has understood
* Hypotheses the user has adopted
* Decisions the user has made
* Actions the user has taken
* Results obtained from action

### 3.3 User Knowledge Must Be Recorded from the User’s Side

The Hypothesis Log is not a place to store hypothesis candidates proposed by AI.

It should record provisional claims that the user has made based on their own understanding.

### 3.4 Use Means Reconnection

Use does not mean that saved information is searchable.

Use means that past understanding, hypotheses, decisions, and action results are reconnected to the user’s current state with the appropriate timing, granularity, cognitive load, and format.

### 3.5 One Turn = One Mode = One Transition

A single response should not mix multiple cognitive modes.

* Do not give many exploration points to a user who wants to execute
* Do not force premature conclusions on a user who wants to explore
* Do not increase the number of options for a user who is trying to decide
* Do not give comparison tables or long explanations to an overloaded user
* Do not confront a defensive user with blunt correctness

### 3.6 Suppression First

The product’s differentiation is not only in what it says.
It is also in what it chooses not to say yet.

Each response internally has:

```text
Intervention {
  detected_state
  target_transition
  payload_type
  max_cognitive_load
  disclosure_level
  included_items
  suppressed_items
  deferred_items
}
```

### 3.7 Silence Is an Action

Not surfacing something, deferring something, or only storing something should be treated as explicit control choices.

## 4. Core Concepts

### 4.1 INTENT

INTENT is the action-state that preserves what the user is currently trying to do.

```text
INTENT =
1. Goal        What the user wants to achieve
2. Why         Why it matters
3. Hypothesis  Which hypothesis the user is acting on
4. Criterion   What makes the action good or bad
5. Next Action What the user will do next
```

INTENT is maintained when:

* The user can state the goal
* The user can state the reason
* The user can state the hypothesis
* The user can state the decision criterion
* The user can state the next action
* The user can accept or reject AI output
* The user can connect AI output to their own Belief Graph or ADR

INTENT is lost when:

* AI output determines the next question
* AI output determines the next decision
* The user only approves, saves, or edits
* The user cannot reject
* Decision criteria become vague
* The next action becomes only another request to AI

### 4.2 Belief Graph

The Belief Graph represents how the user understands the world, what they hypothesize, what they doubt, what they accept as evidence, and which decisions those beliefs connect to.

A Knowledge Graph represents facts about the world.
A Belief Graph represents the user’s understanding structure.

### 4.3 Hypothesis

A Hypothesis is a provisional claim that the user makes, based on their understanding at the time, about the world, an object, the future, or a causal relationship.

A hypothesis is not information.
A hypothesis is a stance toward the world.

### 4.4 ADR / Decision Memory

ADR / Decision Memory records decisions made by the user.

An ADR records:

* Decision
* Rationale
* Options considered
* Selected option
* Rejected options
* Assumptions
* Outcome
* Reconsideration conditions

An ADR is not knowledge itself.
However, when connected to the Belief Graph and Hypothesis Log, it preserves the background of a decision.

### 4.5 Appropriate Cognitive Load

Appropriate cognitive load is the range of load in which the user can maintain INTENT while forming hypotheses, making judgments, and connecting them to action.

```text
L_total = L_intrinsic + L_extraneous + L_productive + L_intent
```

* `L_intrinsic`

  * The complexity of the problem itself

* `L_extraneous`

  * Unnecessary load created by AI output or UI

* `L_productive`

  * Load used for hypothesis formation, distinction-making, integration, and learning

* `L_intent`

  * Load used to hold the goal, reason, criteria, and next action

Appropriate cognitive load satisfies:

```text
L_total <= C_user
```

while maximizing:

```text
L_productive + L_intent
```

### 4.6 Reconnection

Reconnection is the resurfacing of past understanding, hypotheses, decisions, and action results according to the user’s current cognitive state.

Targets of reconnection:

* Past questions
* Past hypotheses
* Past distinctions
* Past reasons for rejection
* Past ADRs
* Past assumptions
* Past action results
* Signs that assumptions have collapsed

## 4.7 Cognitive Network Metaphors

This product uses cognitive network terms as design metaphors.
These terms do not claim to reproduce the brain. They provide a product architecture vocabulary for separating background synthesis, foreground execution, salience-based routing, and drift detection.

### DMN Engine

**DMN** stands for **Default Mode Network**.

In this product, the DMN Engine is the background synthesis engine.

It is responsible for:

* Recombining past notes, conversations, actions, searches, and decisions
* Detecting latent themes across otherwise separate contexts
* Finding unresolved loops
* Detecting weak signals
* Generating periodic insight batches
* Producing future-useful questions the user has not explicitly asked yet

The DMN Engine is most relevant to:

* Exploration
* Reflection
* Meaning-making
* Future simulation
* Hypothesis formation
* Articulation of vague discomfort

The DMN Engine should not interrupt active execution by default.
Its outputs should usually be delivered as deferred InsightCards, unless the SN Router decides that surfacing the insight now is valuable.

Example outputs:

```text
Your recent interests look separate, but they appear to converge on X.
```

```text
A and B are hitting the same underlying constraint.
```

```text
You may be avoiding Y. This has appeared across three separate contexts.
```

### CEN Engine

**CEN** stands for **Central Executive Network**.

In this product, the CEN Engine is the foreground execution engine.

It is responsible for:

* Responding to explicit user intent
* Answering
* Planning
* Comparing
* Deciding
* Drafting
* Prioritizing
* Converting thought into action
* Creating executable artifacts

The CEN Engine is most relevant to:

* Decision-making
* Execution
* Planning
* ADR creation
* Prioritization
* Validation design
* Task conversion

The CEN Engine should produce concise, action-oriented output when the user is in execution mode.
It should not expand into broad exploration unless the user’s state calls for exploration.

Example outputs:

```text
Proceed with this. The next three actions are:
```

```text
The only decision criterion that matters here is A.
```

```text
Send this version, but soften one sentence before sending.
```

### SN Router

**SN** stands for **Salience Network**.

In this product, the SN Router is the salience-based routing and control system.

It is responsible for deciding:

* Whether to activate the CEN Engine now
* Whether a DMN insight should be surfaced now or deferred
* Whether to route to ACC Monitor
* What should be included
* What should be suppressed
* What should be deferred
* How much detail should be disclosed
* Whether to interrupt, ask one question, stay silent, or store only

The SN Router is not a generation engine.
It is a control system.

Its core job is to answer:

```text
Given the user’s current state, intent, and cognitive load,
what is the right intervention now?
```

Possible routes include:

```text
Route {
  CEN_NOW
  DMN_BATCH_LATER
  DMN_INSIGHT_NOW
  ACC_GUARDRAIL
  ACC_PAUSE
  ASK_ONE_QUESTION
  SILENCE
  STORE_ONLY
}
```

### ACC Monitor

**ACC** stands for **Anterior Cingulate Cortex**.

In this product, the ACC Monitor is the drift-detection and conflict-detection system.

It is responsible for detecting:

* Goal Mismatch
* Premise Error
* Constraint Violation
* Irreversibility Error
* Avoidance-disguised Execution
* Local Optimum Trap

The ACC Monitor is most relevant when the user is entering or already in execution mode.

Its job is not to criticize the user.
Its job is to detect whether the proposed action still fits the user’s higher-level goal, assumptions, constraints, and acceptable risk.

The ACC Monitor should act as lane-keeping, not as a brake.

It should not stop execution by default.
It should intervene only at the minimum level required by risk.

Correction levels:

```text
Level 0: Silent
- No intervention when risk is low and the action is reversible

Level 1: Guardrail
- Add a light caution without stopping execution

Level 2: One-question Checkpoint
- Ask one clarifying question before execution

Level 3: Low-risk Experiment
- Convert full execution into a smaller test

Level 4: Pause
- Stop only when the action is irreversible, high-risk, or clearly misaligned
```

Example:

```text
This is worth reducing in scope before sending to everyone.
The current version may optimize for fast response, but it may work against the higher-level goal of building trust.
Send it to five people first, then expand if the response is good.
```

### Relationship Between the Four Components

```text
DMN Engine = background synthesis
CEN Engine = foreground execution
SN Router = salience-based routing
ACC Monitor = drift and conflict detection
```

Operationally:

```text
User input
↓
SN Router detects state and route
↓
CEN Engine responds if the user needs execution or decision support
↓
DMN Engine stores or surfaces background insights when appropriate
↓
ACC Monitor checks for misalignment when execution risk exists
↓
Cognitive Load Governor controls how much is shown
```

Design shorthand:

```text
DMN = what might matter later
CEN = what to do now
SN = what should surface now
ACC = whether this action is drifting from intent
```

## 6. Layer Responsibilities

### 6.1 User Understanding Layer

This layer stores the user’s own structure of understanding.

Includes:

* Belief
* Hypothesis
* Question
* Distinction
* Rejection
* Commitment
* Evidence Standard

Must not include:

* Summaries of AI answers
* External article contents themselves
* General knowledge
* AI hypotheses not adopted by the user
* Pasted research results

### 6.2 External Knowledge Layer

This layer stores information external to the user.

Includes:

* AI Response Memory
* External documents
* Research results
* General knowledge
* Web search results
* Market and contextual updates
* Source reliability

External Knowledge must not be mixed directly into User Understanding.
It connects to the User Understanding Layer only when the user accepts, modifies, or rejects it.

### 6.3 Intent Layer

This layer stores the user’s current action-state.

An IntentFrame cannot be represented by Goal alone.
It must include Why, Hypothesis, Criterion, and Next Action.

```text
IntentFrame {
  id
  goal_id
  why
  hypothesis_id
  criterion
  next_action_id
  source_utterance_id
  confidence
  created_at
  updated_at
}
```

### 6.4 Decision Layer

This layer stores the user’s decisions.

DecisionRecord is the source of truth for decisions.

```text
DecisionRecord {
  id
  title
  decision
  rationale
  considered_options
  selected_option
  rejected_options
  assumptions
  related_hypothesis_ids
  related_belief_ids
  related_goal_ids
  reconsideration_conditions
  expected_result
  actual_result_id
  confidence
  created_at
  updated_at
}
```

### 6.5 Action Learning Layer

This layer connects decisions to actions and updates hypotheses from results.

```text
ActionRecord {
  id
  intent_frame_id
  decision_record_id
  hypothesis_ids
  action
  expected_outcome
  assumptions
  constraints
  reversibility
  risk
  status
  created_at
  executed_at
}
```

```text
ResultRecord {
  id
  action_record_id
  observed_result
  supported_hypothesis_ids
  contradicted_hypothesis_ids
  updated_assumptions
  decision_reconsideration_required
  learning_summary
  created_at
}
```

### 6.6 Reconnection Layer

This layer reconnects past thinking assets to the current state.

Principles:

* Do not surface all related logs
* Return only the 1–3 items most useful for the current INTENT
* Prioritize the user’s own past hypotheses, decisions, and statements over AI external knowledge
* Select by connection value, not by length

State-specific reconnection:

* During exploration:

  * Return questions, hypotheses, discomforts, and counter-hypotheses

* During decision-making:

  * Return assumptions, options, past ADRs, and reasons for rejection

* During action:

  * Return decision rationale, next action, and assumption-collapse conditions

### 6.7 Cognitive Control Layer

This layer controls user state, output load, interruptions, and wrong-direction execution detection.

Includes:

* UserState
* DMN Engine
* CEN Engine
* SN Router
* ACC Monitor
* Cognitive Load Governor
* Intervention Policy

## 8. Cognitive Control Mechanisms

### 8.1 DMN Engine

The DMN Engine is a background insight-generation engine.

Responsibilities:

* Run in the background, independent of explicit intent
* Recombine past notes, conversations, actions, searches, and decisions
* Find unconnected themes
* Generate periodic insight batches
* Generate questions that may become useful later even if the user has not explicitly asked them yet

Output:

```text
InsightCard {
  title
  why_now
  evidence
  suggested_question
  suggested_action_optional
  confidence
  urgency
  defer_until
}
```

Constraints:

* Do not mix into synchronous chat by default
* Deliver as periodic batches
* Maximum 3 items per batch
* Do not interrupt active execution
* Surface only when the SN Router determines that it is valuable now

### 8.2 CEN Engine

The CEN Engine is the foreground execution processor.

Responsibilities:

* Respond to the user’s explicit intent
* Plan
* Decide
* Draft
* Compare
* Convert into tasks
* Convert into executable artifacts

Outputs:

* answer
* plan
* draft
* checklist
* comparison
* recommendation
* task
* email
* calendar action
* document edit
* research brief

Constraints:

* Keep output short in execution mode
* Do not provide unnecessary alternatives by default
* Include at most one caveat
* Make the next action explicit
* Compress decision criteria
* Insert ACC correction only when necessary

### 8.3 SN Router

The SN Router is a salience-based control system.

Responsibilities:

* User state estimation
* Cognitive load estimation
* Interruption decision
* Salience scoring
* Disclosure level selection
* Response length control
* DMN / CEN routing
* Silence / defer decision
* Suppressed item management

Routes:

```text
Route {
  CEN_NOW
  DMN_BATCH_LATER
  DMN_INSIGHT_NOW
  ACC_GUARDRAIL
  ACC_PAUSE
  ASK_ONE_QUESTION
  SILENCE
  STORE_ONLY
}
```

The SN Router is not a generative system.
It is a control system that decides what to surface now, what to defer, and what to suppress.

### 8.4 ACC Monitor

The ACC Monitor is a drift-detection system.

It detects:

* Goal Mismatch
* Premise Error
* Constraint Violation
* Irreversibility Error
* Avoidance-disguised Execution
* Local Optimum Trap

Responsibilities:

* Detect when the user has entered execution mode while facing the wrong direction
* Detect drift between local intent and higher-level goals
* Detect premise errors
* Detect constraint violations
* Detect premature movement into irreversible action
* Detect when avoidance is disguised as execution

Constraints:

* Do not stop the user every time
* Act as lane-keeping, not as a brake
* Keep intervention minimal

Misalignment Risk:

```text
Misalignment Risk =
  goal_drift
  + premise_uncertainty
  + constraint_violation
  + irreversibility
  + opportunity_cost
  + avoidance_signal
  - reversibility
  - user_confidence_calibration
```

Correction Levels:

```text
Level 0: Silent
- Say nothing when risk is low, action is reversible, and learning value exists

Level 1: Guardrail
- The direction is mostly right; add only a light caution

Level 2: One-question Checkpoint
- There may be drift from the higher-level goal; ask one question before execution

Level 3: Low-risk Experiment
- Convert full execution into a smaller test

Level 4: Pause
- Stop only when the action is irreversible, high-risk, conflicts with higher-level goals, or relies on highly uncertain assumptions
```

### 8.5 Cognitive Load Governor

The Cognitive Load Governor controls output so that the user can maintain INTENT.

Responsibilities:

* Response length control
* Number of issues shown
* Number of alternatives shown
* Amount of rationale disclosed
* Number of reconnected memories shown
* Interruption intensity control
* Pre-save friction control

State-specific output policies:

```text
Execution:
- Answer first
- Max 1 caveat
- Next action required
- No long exploration

Research:
- Branches over conclusions
- Future decision points
- No premature recommendation unless asked

Decision:
- Compress criteria
- Identify reversible vs irreversible
- Recommend one path
- Defer non-critical uncertainty

Defense:
- Validate
- Reduce threat
- Offer low-risk step
- Avoid direct confrontation

Overload:
- Reduce to one next step
- Explicitly park other issues
- No tables unless requested
```

## 9. Core Processing Flow

### 9.1 Common Flow

```text
1. Receive user utterance
   ↓
2. Separate AI external knowledge from user-derived knowledge
   ↓
3. Extract understanding, hypotheses, questions, and distinctions from user utterance
   ↓
4. Record in Belief Graph / Hypothesis Log
   ↓
5. If a decision occurs, create a DecisionRecord
   ↓
6. If an action occurs, connect it to an ActionRecord
   ↓
7. If a result occurs, record it as a ResultRecord
   ↓
8. Detect UserState
   ↓
9. SN Router selects Route
   ↓
10. ACC Monitor detects drift if needed
   ↓
11. Reconnection Layer narrows past logs to 1–3 items
   ↓
12. Cognitive Load Governor adjusts output load
   ↓
13. CEN / DMN / Intervention responds
   ↓
14. Capture Feedback
```

```text
User explores
↓

↓
User Understanding Extraction
↓

↓
Past questions / distinctions / hypotheses retrieval
↓

↓

```

Support:

```text
↓
Options extraction
↓
Assumption extraction
↓

↓

↓

```

## 10. Pre-save Friction

### 10.1 Purpose

Do not save AI output directly as user knowledge.
Force it to pass through user understanding, acceptance, modification, or rejection.

### 10.2 Rules

* Avoid one-click saving
* Require “one sentence in the user’s own words” before saving
* Require assumptions and rejected options before creating an ADR
* Require acceptance, modification, or rejection before adding to the Hypothesis Log
* Save AI output as AIResponse by default
* Connect it to the User Understanding Layer only when the user explicitly understands or judges it

### 10.3 Storage Destination Rules

```text
What AI said
→ AIResponse

External documents / research results
→ ExternalKnowledgeItem

Hypotheses, discomforts, and distinctions stated by the user
→ UserBelief / UserHypothesis / Question / Distinction

Judgments accepted or rejected by the user
→ DecisionRecord

Actions and results
→ ActionRecord / ResultRecord
```

## 14. Privacy and Trust

### 14.1 User Control

* The user can view, edit, and delete memories
* Inferred goals and preferences are visible
* The user can choose “do not use this memory”
* Proactive intervention can be turned off
* The system can display whether information is AI-derived or user-derived

### 14.2 Transparency

* For important interventions, briefly show the basis
* Do not over-explain during Execution
* Provide “why this was surfaced now” when needed
* Anything saved to the User Understanding Layer must be traceable back to source utterances

### 14.3 Avoid Manipulation

* Support the user’s goal achievement
* Handle conflicts between explicit and inferred goals carefully
* Avoid overly directive intervention when the user is in Defense mode
* Any behavior-change intervention must align with the user’s benefit
* AI must not overwrite user understanding

## 15. Risks and Mitigations

### 15.1 AI Output Warehouse Failure

Problem:

* AI answers and research results are saved directly and confused with user knowledge

Mitigation:

* Separate AIResponse, ExternalKnowledge, and UserUnderstanding
* Add pre-save friction
* Require user acceptance, modification, or rejection

### 15.2 False Positive Misalignment

Problem:

* ACC Monitor stops execution that was actually correct

Mitigation:

* Do not stop when reversibility is high
* Start with Guardrail
* Use Pause only for high-risk cases

### 15.3 Over-personalization

Problem:

* The system overfits to an outdated model of the user

Mitigation:

* Use confidence values
* Decay old memories
* Allow user correction

### 15.4 Annoying Proactivity

Problem:

* DMN Batch or SN interruptions become noisy

Mitigation:

* Control notification frequency
* Limit InsightCards to 3
* Learn strongly from dismissed signals
* Treat silence as an explicit action

### 15.5 Generic AI Output

Problem:

* The product does not differ from standard AI chat

Mitigation:

* Enforce mode purity
* Track suppressed_items internally
* Limit output length by state
* Design “do not say yet” as a first-class behavior

### 15.6 Manipulative Feel

Problem:

* The user feels observed or manipulated by state inference

Mitigation:

* Make intervention reasons explainable
* Make settings configurable
* Explicitly confirm higher-level goals
* Avoid strong nudges

## 17. Final Definition

Human Thought Augmentation System is a system that strengthens human thinking by not confusing AI external knowledge with human knowledge, by modeling the user’s own understanding, hypotheses, decisions, and actions, and by reconnecting them according to the user’s current cognitive state.

To do this, it uses a DMN Engine, CEN Engine, SN Router, ACC Monitor, and Cognitive Load Governor to control AI output and memory resurfacing so that the user can maintain INTENT within an appropriate cognitive load range.
